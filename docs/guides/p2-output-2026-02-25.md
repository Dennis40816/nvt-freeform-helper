## T11 `N6` Edge Spill EN A/B Evaluation Conclusion

### Current State
- Settings source: `src/FreeformHelper.Application/Settings/MatchingSettings.cs` `EnableFreeformEdgeSpecialization`
- Algorithm entry: `src/FreeformHelper.Application/Services/FreeformDetector.cs`
- UI entry: `src/FreeformHelper.UI/Views/SettingsWindow.axaml` `Edge spill EN`
- Test coverage: `tests/FreeformHelper.Tests/Application/Freeform/FreeformDetectorTests.cs`

### Conclusion
1. `Edge spill EN` should still be kept.
2. It solves the case where a tiny spill at the boundary is suppressed by the global TH. It is not general freeform detection.
3. Keep the default as `OFF` (conservative). Change the description text to "Boundary tiny spill specialization" to avoid misunderstanding.

### A/B Validation Proposal
1. A: `OFF`, B: `ON`, with fixed `3635` and the same TH set.
2. Compare metrics: `None->X/Y/XY` conversion count, Step5 row count, validation incoming/outgoing difference.
3. Only consider promoting the default if B adds valid rows only at boundary pads, and no noise spreads into the middle region.

## T12 `N3` CAD->Regular Weighted Allocation Design Draft

### Current State
- Existing weight calculation: `src/FreeformHelper.Application/Services/NotchAllocationService.cs`
- Existing target allocation: `src/FreeformHelper.Application/Services/NotchV22TargetAllocationService.cs`

### Draft (v2)
1. Candidate set:
   `overlapArea > epsilon` and has a valid association with the anchor IC.
2. Base weight:
   `w0 = overlapArea / cadArea` (keep current behavior for intuitiveness).
3. Boundary penalty:
   For non-boundary pads or pads with high blocker risk, apply penalty factor `p in [0,1]`.
4. Normalization:
   Within the same IC, compute `w = (w0*p)/sum(w0*p)`, to avoid direct competition across ICs.
5. Export rounding:
   Only do percentage rounding and saturation at the end. Keep the raw floating-point values in the trace for debugging.

### New Trace Fields Needed
1. `baseWeight`
2. `penaltyFactor`
3. `normalizedWeight`
4. `roundingDelta`
